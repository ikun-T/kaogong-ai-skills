# 来源证据与讲师归因

来源文件见 `sources.json`；方法文件见 `methods.json`。一条视频可有多个核验片段，阅读范围只覆盖已登记部分。

## 证据级别

| evidence_level | 实际取得的材料 | 能支持什么 |
|---|---|---|
| transcript | 可读取字幕及可定位时间段 | 该段文字讲到的方法；自动字幕仍需核对数字、否定词和公式 |
| video_sample | 实际读取的画面／音频片段 | 已观察到的局部板书或讲解，保留时间位置与观察方式 |
| article_body | 作者／机构公开正文或官方文件 | 正文中的明确论述；与视频内容分开 |
| description_only | 实际打开的视频简介、分P目录 | 简介中的明确表述或课程结构，不能扩展为整课方法 |
| search_only | 搜索索引片段 | 发现候选、有限元数据；不用于确认讲师个人方法 |
| unavailable | 没有取得足以核验的内容 | 仅保留访问失败记录 |

`description_only` 若仅为目录，具体解题步骤应为空。发布者明确在简介写出操作规则时，可做局部证据，但须表述为“公开简介提出”，不能表述为“视频详细论证”。

## 方法卡

每卡记录：`id`、`name`、`module`、`status`、`attribution`、`triggers`、`steps`、`limits`、`evidence`、`example`。

- `source_verified`：至少一条可核验来源支撑卡片核心教学规则。`evidence` 记录 `source_id`、`locator`、`support`；来源与卡片不可循环证明。
- `original_design`：项目依据题型与数学／逻辑规则设计的流程，`attribution` 必须明确为本项目；可以有课程主题的启发来源，但不能当作归因证据。
- `candidate`：只有主题／目录或尚未核验的说法；不得作为讲师方法调用。

讲师卡应把“已经核验的方法”“只确认到的课程主题”“仍需读取的材料”分开。多名上传者可能是同一位主讲者，搬运号不能计作新老师；不能因名字相近自动合并。

## 热门与长尾

播放量、关注量只是在某次检索可见的快照，不是教学质量或独创性指标。记录快照的日期、对象（单视频／合集／频道）、来源和约数。没有指标时写“未知”，不要补排行。抽样同时寻找较大受众来源与较小受众个人创作者，不声称覆盖全站。

## 内容与来源的权利

只发布自己写的摘要、来源链接、可复现的原创题与代码。网页可访问不表示版权开放，MIT 许可不覆盖第三方视频、字幕、讲义和题目。完整字幕只在用户合法取得并允许处理时作为本地输入；默认不纳入 Git。不要使用明显以“付费课程搬运／代付”宣传的集合扩展训练库。

## 新来源纳入流程

确认标题、URL、主讲／上传者关系 → 读取实际内容并登记范围 → 抽出一条可执行规则 → 写前提与失败情况 → 用原创题检验 → 再决定归因或保持候选。核验成功之前保留访问状态，不靠泛化常识填充讲师卡。
